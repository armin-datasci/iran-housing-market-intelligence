# Data and Artifact Access

## Purpose

This project separates **version-controlled source code** from **large reproducibility artifacts**. GitHub is the canonical source-code/documentation repository; the frozen Google Drive runtime bundle is the canonical reviewer-facing source for the large Raw, Silver, Gold, and accepted generated artifacts used by the validated Colab workflow.

**Frozen runtime/data bundle:**

**Validated Colab:**

https://colab.research.google.com/drive/1qc-qQ5ciyIW5NhQjRCpn8XidoMG_2ahh

## Why the large artifacts are not stored in Git

The project intentionally excludes `external_data/`, `data/`, and generated `outputs/` from normal Git history. The raw CSV is approximately 781 MB and the accepted Silver Master approximately 356 MB, before counting Gold, QA, figures, model artifacts, and intermediate analytical outputs. Keeping those binaries outside Git avoids repository bloat while preserving a frozen, reproducible delivery path.

The source repository therefore answers **how the project works**; the runtime bundle provides **the data and accepted artifacts needed to reproduce/review it**.

## Key data contracts

### Raw

- 1,000,000 listing rows and 60 source columns in the accepted source audit.
- Monetary values are listing **asking prices**, not verified transaction prices.
- Raw data remains an external/source input rather than a persisted Bronze data layer.

### Silver

- `data/silver/silver_master.parquet` is the single canonical row-level analytical dataset.
- The accepted release contains 1,000,000 rows and the promoted canonical schema/documentation covers 196 fields.
- Silver is read-only downstream: M3/M4 do not recreate M2 cleaning, duplicate, outlier, currency, or price-regime logic.

### Gold

- 10 canonical marts.
- 5 conformed dimensions.
- 13 active single-direction physical relationships in the accepted BI contract.
- Exact listing coordinates are excluded from Gold.

## Accepted output families

The runtime bundle restores the accepted outputs used for auditability and presentation, including:

- M1 data-audit and closeout evidence;
- M2 standardization, missingness, duplicate/entity-resolution, outlier, currency, price-regime, final-metric, and quality-gate evidence;
- M3 analysis-population, spatial-quality, market-map, monthly-market, Market Temperature, price-driver/AVM, seller-type, text-signal, and segmentation artifacts;
- M4 Gold marts, dimensions, metadata, and QA;
- final statistical-governance, environment-snapshot, and pipeline-readiness artifacts;
- selected report figures and aggregate map outputs.

Task-level QA is intentionally kept as technical evidence rather than treated as business data in Gold.

## Restore and run

### Option A - Reviewer / Colab path (recommended)

Open the validated Colab notebook. Its bootstrap workflow:

1. clones the canonical GitHub repository;
2. installs `requirements.txt`;
3. downloads the frozen runtime bundle;
4. validates and restores the bundle to the project-relative paths;
5. checks runtime/artifact readiness;
6. executes the final evidence notebook from a fresh runtime.

This is the fastest reproducible route for reviewers because it does not require manually reconstructing the local directory tree.

### Option B - Full local pipeline

From a clean clone:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
```

Restore the bundle so its `external_data/`, `data/`, and `outputs/` paths align with the repository root. Then run:

```powershell
python .\scripts\run_pipeline.py --start-at m1 --stop-after reports
```

If rebuilding Silver from Raw is intentionally required, use the pipeline's explicit rebuild control rather than editing downstream artifacts manually.

## Environment snapshot

The final reporting stage writes:

```text
outputs/qa/final_pipeline/environment_versions.json
```

This file records Python/runtime information and installed versions for the declared/core distributions without recording usernames, home directories, environment variables, secrets, or absolute interpreter paths.

`requirements.txt` is therefore the direct-dependency declaration, while `environment_versions.json` is the accepted resolved-runtime reference. Version pins should only be promoted into a lockfile from a validated snapshot; they should not be guessed.

## Spatial and privacy boundaries

The spatial-quality task can use listing-level coordinates internally for QA, including external ADM2 point-in-polygon and stratified reverse-geocode validation. Publication follows an aggregate-only policy:

- exact listing coordinates are not published in Gold;
- exact listing coordinates are not published in Power BI, Streamlit, or the public FastAPI service;
- public map/report outputs use aggregate or sanitized geographic evidence;
- external boundary/reference files document independent QA inputs, not private listing locations.

## Interpretation boundaries

Restoring the artifacts reproduces the project's analytical evidence, but does not change these claim boundaries:

- asking price is not transaction price;
- platform listing activity is not physical inventory, liquidity, or absorption;
- Market Temperature is a listing-market proxy;
- model effects and seller/text comparisons are observational/predictive, not causal;
- the AVM is a research/prototype diagnostic, not a production valuation guarantee;
- released market segments are descriptive market types.
